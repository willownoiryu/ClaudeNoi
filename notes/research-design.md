## 1. 연구 방법 개요

- ✅ **방법:** 온라인 실험, 3 × 2 피험자 간 요인 설계 (참가자를 6개 조건 중 하나에 무작위 배정)
- ✅ **상황:** 클라우드 스토리지 용량이 가득 차서 서비스가 알림을 보여주는 순간
- ✅ **요인 1 — 톤 (압박 수준):** 차분 / 약한 압박 / 강한 압박
- ✅ **요인 2 — 출구 (대안 제시):** 결제만 / 결제 + AI 정리 제안
- ✅ **측정:** 행동(결제·정리·무시)과 서비스에 대한 신뢰
- ❓ **자극물 형태:** 시나리오(화면 이미지 + 설문) vs 인터랙티브 프로토타입 (아래 6절)

## 2. 실험 조건 (3 × 2 = 6개)

### 요인 1: 톤 (압박 수준)

Luguri & Strahilevitz(2021)의 "약한 다크 패턴 vs 강한 다크 패턴" 비교와
Miller 외(2007)의 통제적 언어(controlling language) 연구를 바탕으로 3단계로 설계.

| 수준 | 특징 | 알림 문구 예시 (❓ 예비조사로 확정) |
| --- | --- | --- |
| 차분 | 사실만 전달, 선택은 사용자에게 | "저장 공간을 모두 사용했어요. 필요하면 용량을 늘릴 수 있어요." |
| 약한 압박 | 불이익을 구체적으로 알림 | "저장 공간이 가득 찼어요. 업그레이드하지 않으면 새 사진과 파일이 백업되지 않아요." |
| 강한 압박 | 경고 표시, 통제적 언어("지금 바로"), 시간 제한 | "⚠ 저장 공간 초과! 지금 바로 업그레이드하세요. 백업과 동기화가 중단됩니다. 오늘만 첫 달 50% 할인" |

### 요인 2: 출구 (대안 제시)

Tannenbaum 외(2015)의 "위협 + 행동 가능한 대안(효능 메시지)" 원칙을 바탕으로 설계.

| 수준 | 화면에 보이는 선택지 |
| --- | --- |
| 결제만 (압박형) | [업그레이드] [나중에] |
| 결제 + AI 정리 제안 (도움형) | [업그레이드] [AI 정리 제안 보기 — 정리하면 약 4.2GB 확보 가능] [나중에] |

### 6개 조건 한눈에 보기

| | 결제만 | 결제 + AI 정리 제안 |
| --- | --- | --- |
| **차분** | 조건 1 | 조건 2 |
| **약한 압박** | 조건 3 | 조건 4 |
| **강한 압박** | 조건 5 (가장 "압박형") | 조건 6 |

**설계 원칙**
- 톤과 출구 **외의 차이는 없게** 화면 구성, 색, 문구 길이를 최대한 맞춤
- 할인 문구처럼 강한 압박에만 들어가는 요소는 "강한 압박"의 구성 요소로 명시하고 논문에 기술
- ❓ **"결제만" 조건에서 정리를 어떻게 측정할지:** 알림을 닫은 뒤 "다음에 무엇을 하시겠어요? (결제 / 직접 파일 정리 / 아무것도 안 함)"을
  모든 조건에서 똑같이 묻는 방식을 추천 → 조건 간 행동 비교가 공정해짐

## 3. 변수와 측정 도구

| 구분 | 변수 | 측정 방법 | 출처 |
| --- | --- | --- | --- |
| 독립변수 | 톤 (3수준) | 실험 조건 | Luguri & Strahilevitz(2021), Miller 외(2007) |
| 독립변수 | 출구 (2수준) | 실험 조건 | Tannenbaum 외(2015), Witte(1992) |
| 종속변수 | **행동** | 결제 / 정리 / 무시 중 선택 | — |
| 종속변수 | **서비스 신뢰** | 신뢰 척도 (능력·호의·정직 차원) | McKnight 외(2002) |
| 매개변수 | 심리적 반발 | 분노 + 부정적 인지 | Dillard & Shen(2005), Rains(2013) |
| 매개변수 | 지각된 불쾌감(짜증) | 리커트 척도 | Voigt 외(2021), 조보민 외(2023) |
| 탐색 변수 | 조작 의도 지각 | "이 서비스가 나를 조종하려 한다고 느꼈다" | Friestad & Wright(1994) 설득 지식 모델 |
| 조작 점검 | 압박감, 대안 인지 | "이 알림은 압박적이었다", "결제 외 다른 방법이 제시되었다" | — |
| 통제변수 | 디지털 저장강박 성향 | DHQ 10문항 | Neave 외(2019) |
| 통제변수 | 스토리지 이용 현황, 유료 이용 여부, 인구통계 | 설문 | — |

해외 척도는 **번역-역번역**으로 한국어판을 만들고 그 절차를 논문에 기술.

## 4. 참가자

- **대상:** 클라우드 스토리지(Google Drive, iCloud, 네이버 MYBOX 등)를 쓰고 있는 성인
- **표본 크기:** 중간 효과 크기(f = 0.25), 유의수준 .05, 검정력 .80 기준 계산
  - 톤 주효과·톤×출구 상호작용 (자유도 2): **최소 158명**
  - 출구 주효과 (자유도 1): 최소 128명
  - → **조건당 30명, 총 180명**을 목표로 하고, 불성실 응답 제외를 고려해 **약 200명 모집**
- **모집:** 온라인 패널(엠브레인, 오픈서베이 등) 또는 학교 커뮤니티·SNS (❓ 예산 확인)

## 5. 절차

1. 동의서 → 스토리지 이용 현황
2. DHQ (실험 조작 전에 측정)
3. 상황 설명: "당신은 평소 쓰던 클라우드 드라이브에 사진을 올리려 합니다…"
4. 무작위 배정된 조건의 알림 화면 제시
5. 행동 선택 (결제 / 정리 / 무시)
6. 반발, 불쾌감, 서비스 신뢰, 조작 의도 지각
7. 조작 점검, 인구통계
8. 디브리핑 (실제 서비스·결제가 아님을 안내)

예상 소요 시간: 10~15분

## 6. 자극물 형태 (❓ 결정 필요)

| | A. 시나리오 방식 | B. 인터랙티브 프로토타입 |
| --- | --- | --- |
| 내용 | 상황 설명 + 알림 화면 이미지 → 설문 | 가상 드라이브를 쓰다가 용량 초과 → 알림 → 버튼 클릭 → (정리 선택 시) AI 제안 화면 |
| 행동 측정 | 선택 의향 | 실제 클릭 |
| 장점 | 제작이 쉬움 | 설득력이 높고, AI 정리 제안을 실제로 체험하게 할 수 있음 |
| 단점 | 의향과 실제 행동이 다를 수 있음 | 제작 시간 필요 |

→ "AI 정리 제안"이 핵심 조건이므로, 제안 내용을 실제로 보여줄 수 있는 **B를 추천**.

## 7. 분석 계획

| 목적 | 분석 방법 |
| --- | --- |
| 조작 점검 | 톤별 압박감 차이 (ANOVA), 출구별 대안 인지 차이 (t-검정) |
| 행동 (결제·정리·무시) | 다항 로지스틱 회귀 (톤, 출구, 톤×출구) |
| 신뢰, 반발, 불쾌감 | 3 × 2 이원분산분석(two-way ANOVA) + 단순 주효과 분석 |
| 반발이 톤 → 신뢰를 매개하는가 | 매개 분석 (PROCESS Model 4) |
| 출구가 그 매개 경로를 약화하는가 | 조절된 매개 분석 (PROCESS Model 7) |
