# 연구 설계 (초안 v2 — 설득 이론 반영)

> 실제 서비스 데이터 없이 **온라인 실험**으로 진행. 확정된 것은 ✅, 결정이 필요한 것은 ❓로 표시.
> 이론적 틀: **보호 동기 이론** (Rogers, 1975) — 용량 부족 = 위협, 정리·결제 = 대처 행동

## 1. 연구 방법 개요

- ✅ **방법:** 온라인 실험 (참가자를 무작위로 조건에 배정하는 피험자 간 설계)
- ✅ **상황:** 클라우드 스토리지 용량이 가득 찬 순간, 서비스가 알림을 보여줌
- ✅ **조작:** 알림의 **설득 전략** (5개 조건)
- ❓ **자극물 형태:** 시나리오 vs 인터랙티브 프로토타입 (아래 6절)

## 2. 실험 조건 (설득 전략)

보호 동기 이론의 두 요소(위협 평가, 대처 평가)와 설득 시스템 설계 모델(Oinas-Kukkonen & Harjumaa, 2009)의 원칙을 바탕으로 구성.
❓ 문구는 예비조사로 확정.

| 조건 | 설득 전략 | 알림 문구 예시 | 이론적 근거 |
| --- | --- | --- | --- |
| 0. 통제 | 사실만 전달 (현재 일반적인 방식) | "저장 공간이 가득 찼습니다." | 비교 기준 |
| 1. 위협 제시 | 불이익을 구체적으로 알림 | "저장 공간이 가득 차서 새 사진이 백업되지 않고 있어요." | 보호 동기 이론의 위협 평가 (Rogers, 1975) |
| 2. 위협 + 대처 정보 | 위협 + 쉽고 효과 있는 정리 방법 | 조건 1 문구 + "1년 넘게 열지 않은 파일 23개(4.2GB)를 정리하면 해결돼요. 지운 파일은 30일 안에 복구할 수 있어요." | 대처 평가 (Rogers, 1975), 효능 메시지 (Tannenbaum 외, 2015; Witte, 1992) |
| 3. 과업 단순화 | 정리를 대신 해줌 (기본값) | 조건 1 문구 + "오래된 파일 23개(4.2GB)를 휴지통으로 옮길게요. 30일 안에 복구할 수 있어요. [괜찮아요] [직접 고를게요]" | 설득 시스템 설계 모델의 과업 단순화(reduction), 기본값 넛지 |
| 4. 사회적 증거 | 다른 사용자의 행동 제시 | 조건 1 문구 + "비슷한 사용자의 70%는 한 달에 한 번 오래된 파일을 정리해요." | 설득 시스템 설계 모델의 사회적 지원 (탐색적) |

**설계 원칙**
- 조건 1~4는 **같은 위협 문구에서 출발**하고 전략 요소만 더함 → 조건 간 차이가 설득 전략 때문임을 보여줄 수 있음
  (특히 조건 1 vs 2 비교가 핵심: 대처 정보의 순수 효과)
- 모든 조건에서 **정리·결제·나중에 선택지를 똑같이** 제시: [정리하기] [업그레이드] [나중에]
- 문구 길이와 화면 구성은 최대한 맞추고, 차이가 남는 부분은 논문에 기술

> 대안: 조건을 줄여 **2 × 2 설계**로 "위협(없음/있음) × 대처 정보(없음/있음)"를 보면 보호 동기 이론의 두 요소를
> 더 깔끔하게 검증할 수 있음 (필요 인원 약 128명). 과업 단순화·사회적 증거는 빠짐.

## 3. 변수와 측정 도구

| 구분 | 변수 | 측정 방법 | 출처 |
| --- | --- | --- | --- |
| 독립변수 | 설득 전략 | 실험 조건 (무작위 배정) | — |
| 매개변수 | **지각된 위협** (심각성, 취약성) | 리커트 7점 | 보호 동기 이론 척도를 맥락에 맞게 수정 ❓ 척도 출처 조사 필요 |
| 매개변수 | **정리 효능감** (반응 효능감, 자기 효능감, 반응 비용) | 리커트 7점 | 위와 같음 |
| 매개변수 | **심리적 반발** (설득의 비용) | 분노 + 부정적 인지 | Dillard & Shen(2005), Rains(2013) |
| 종속변수 | 행동 | 정리 / 결제 / 무시 중 선택 (프로토타입이면 실제 클릭) | — |
| 종속변수 | 정리 의향, 결제 의향 | 리커트 7점 | Mäntymäki 외(2020) 참고 |
| 종속변수 | 서비스 태도 | 리커트 7점 | ❓ 척도 선정 |
| 조절변수 | 디지털 저장강박 성향 | DHQ 10문항 | Neave 외(2019) |
| 조작 점검 | 위협·대처 정보를 인식했는가 | "알림에 불이익이 언급되었다", "해결 방법이 제시되었다" | — |
| 통제변수 | 스토리지 이용 현황, 유료 이용 여부, 인구통계 | 설문 | — |

해외 척도는 **번역-역번역**으로 한국어판을 만들고 그 절차를 논문에 기술.

## 4. 참가자

- **대상:** 클라우드 스토리지(Google Drive, iCloud, 네이버 MYBOX 등)를 쓰고 있는 성인
- **표본 크기:** 중간 효과 크기(f = 0.25), 유의수준 .05, 검정력 .80 기준 (최종 확정 시 G*Power로 다시 계산)
  - 조건 5개: 약 **200명** (조건당 40명)
  - 2 × 2 설계: 약 128명 (조건당 32명)
  - 불성실 응답 제외를 고려해 10~20% 더 모집
- **모집:** 온라인 패널(엠브레인, 오픈서베이 등) 또는 학교 커뮤니티·SNS (❓ 예산 확인)

## 5. 절차

1. 동의서 → 스토리지 이용 현황
2. DHQ (실험 조작 전에 측정해야 알림의 영향을 받지 않음)
3. 상황 설명: "평소 쓰던 클라우드 드라이브에 사진을 올리려는데…"
4. 무작위 배정된 조건의 알림 제시
5. 행동 선택 (정리 / 결제 / 나중에)
6. 지각된 위협, 정리 효능감, 심리적 반발, 정리·결제 의향, 서비스 태도
7. 조작 점검, 인구통계
8. 디브리핑 (실제 서비스·결제가 아님을 안내)

예상 소요 시간: 10~15분

## 6. 자극물 형태 (❓ 결정 필요)

| | A. 시나리오 방식 | B. 인터랙티브 프로토타입 |
| --- | --- | --- |
| 내용 | 상황 설명 + 알림 화면 이미지 → 설문 | 가상 드라이브(파일 50개 내외)를 쓰다가 용량 초과 → 알림 → 실제로 정리하거나 버튼 클릭 |
| 행동 측정 | 선택 의향 | 실제 행동 (지운 파일 수, 클릭) |
| 장점 | 제작이 쉬움 | 설득력이 높고, 대처 정보가 실제 정리 행동으로 이어지는지 볼 수 있음 |
| 단점 | 의향과 실제 행동이 다를 수 있음 | 제작 시간 필요 (Figma 프로토타입 또는 간단한 웹페이지) |

→ 일정이 허락하면 B를 추천. 어렵다면 A로 하고 한계에 명시.

## 7. 분석 계획

| 목적 | 분석 방법 |
| --- | --- |
| 조작 점검 | 조건별 위협·대처 정보 인식 차이 (ANOVA) |
| 조건별 행동 비교 | 다항 로지스틱 회귀 또는 카이제곱 검정 |
| 조건별 위협·효능감·반발 비교 | 일원분산분석 + 사후 검정 (핵심 비교: 조건 1 vs 2, 2 vs 3) |
| 정리 효능감의 매개 효과 (H2-3) | 매개 분석 (PROCESS Model 4, 다범주 독립변수) |
| 저장강박 성향의 조절 효과 (H4) | 조절된 매개 분석 (PROCESS Model 7) |
