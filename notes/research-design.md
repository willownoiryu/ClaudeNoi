# 연구 설계 (초안)

> 실제 서비스 데이터 없이 **온라인 실험**으로 진행. 확정된 것은 ✅, 결정이 필요한 것은 ❓로 표시.

## 1. 연구 방법 개요

- ✅ **방법:** 온라인 실험 (참가자를 무작위로 조건에 배정하는 피험자 간 설계)
- ✅ **상황:** 클라우드 스토리지 용량이 가득 찬 순간, 서비스가 넛지 화면을 보여줌
- ❓ **자극물 형태:** 아래 두 방식 중 선택

| | A. 시나리오(비네트) 방식 | B. 인터랙티브 프로토타입 방식 |
| --- | --- | --- |
| 내용 | "당신의 드라이브가 가득 찼습니다" 상황 설명 + 넛지 화면 이미지를 보여주고 설문 | 가상의 드라이브(파일 50개 내외)를 직접 써보다가 용량 초과 → 넛지 화면 → 실제로 정리하거나 결제 버튼을 누름 |
| 측정 | 정리·결제 **의향** (설문) | 실제 **행동** (지운 파일 수, 결제 버튼 클릭 여부) + 설문 |
| 장점 | 만들기 쉽고 설문 도구(Qualtrics, 구글 폼)만으로 가능 | 결과 설득력이 높음, 의향과 행동의 차이도 볼 수 있음 |
| 단점 | 의향이 실제 행동과 다를 수 있음 | 프로토타입 제작 시간 필요 (Figma 프로토타입 또는 간단한 웹페이지) |

→ **추천:** 일정이 허락하면 B. 어렵다면 A로 하고, 한계에 "의향 측정"을 명시.

## 2. 실험 조건 (넛지 유형)

Caraban 외(2019)의 넛지 분류와 Bruns & Perino(2023)의 비교 방식을 바탕으로 한 후보. 핵심 4개(통제·추천·기본값·손실 강조)를 주요 비교 대상으로 두고, 사회적 규범은 **탐색적 조건**으로 둬요. ❓ 사회적 규범을 실험에 넣을지(5개) 뺄지(4개) 확정 필요.

| 조건 | 화면 예시 | 근거 |
| --- | --- | --- |
| 0. 통제 (현재 일반적인 방식) | "저장 공간이 가득 찼습니다. [용량 업그레이드]" | 비교 기준 |
| 1. 정리 대상 추천 | "1년 넘게 열지 않은 파일 23개(4.2GB)를 찾았어요. [확인하고 정리하기] [업그레이드]" | KondoCloud(Brackenbury 외, 2021)의 추천 방식 |
| 2. 기본값 (자동 정리 제안) | "오래된 파일 23개를 휴지통으로 옮길게요. 30일 안에 복구할 수 있어요. [괜찮아요] [직접 고를게요]" | 기본값 넛지. 복구 가능성 안내는 Ramokapane 외(2022) |
| 3. 손실 프레이밍 | "공간이 부족해 새 사진이 백업되지 않고 있어요. [정리하기] [업그레이드]" | 손실 회피, 위협 소구(Witte, 1992) |
| 4. 사회적 규범 (탐색) | "비슷한 사용자의 70%는 한 달에 한 번 정리해요. [정리하기] [업그레이드]" | 사회적 증거(Oinas-Kukkonen & Harjumaa, 2009) |

각 조건이 어떤 설득 원리로 작동하는지는 [`thesis-outline.md`](thesis-outline.md) 5-1절에 정리했어요.

기본값 조건은 정리가 **이미 선택된 상태**로 제시하고 사용자가 거부해야 하는 형태로 만들어요. "자동으로 정리하기" 버튼만 보여주면 추천 조건과 차이가 약해져요.

설계 원칙: 모든 조건에서 **정리와 결제 두 선택지를 똑같이 보여주고**, 문구 길이와 화면 구성을 최대한 맞춤 (넛지 방식 외 다른 차이 제거).

> 대안: 조건을 줄이고 **2×2 설계**로 "넛지 방식(추천 vs 기본값) × 선택권 안내(있음 vs 없음)"를 보면,
> 넛지와 다크 패턴의 경계(선택권 안내가 반발을 줄이는가)를 직접 검증할 수 있음.

## 3. 변수와 측정 도구

| 구분 | 변수 | 측정 방법 | 출처 |
| --- | --- | --- | --- |
| 독립변수 | 넛지 유형 | 실험 조건 (무작위 배정) | — |
| 종속변수 | 선택 | 정리 / 결제 / 무시 중 선택 (B 방식이면 실제 클릭) | — |
| 종속변수 | 정리 의향 | 리커트 7점 척도 2~3문항 | 연구자 개발 → 예비조사로 검증 |
| 종속변수 | 결제 의향 | 리커트 7점 척도 | Mäntymäki 외(2020), Wagner 외(2014) 참고 |
| 부정적 결과변수 (매개는 탐색) | **심리적 반발 (불쾌감)** | 분노 4문항 + 부정적 인지 | Dillard & Shen(2005) |
| 종속변수 | 서비스 태도 | 넛지 경험 이후 서비스에 대한 태도, 리커트 7점 | ❓ 척도 미정 |
| 종속변수 | 지각된 침해감 | 7문항 | Edwards 외(2002) |
| 매개변수 | 지각된 위협 | 용량 부족의 심각성·가능성 인식, 리커트 7점 | 보호 동기 이론(Rogers, 1975) ❓ 척도: Witte 외(1996) 참고 |
| 매개변수 | 정리 효능감 | 반응 효능감(정리하면 해결된다) + 자기 효능감(쉽게 할 수 있다)을 구분해 측정, 리커트 7점 | Rogers(1975), Witte(1992) ❓ 척도: Witte 외(1996) 참고 |
| 매개변수 (선택) ❓ | 반응 비용 | 정리가 번거롭고 시간이 든다는 인식, 리커트 7점 | Rogers(1975) ❓ 척도 미정 |
| 조절변수 | 디지털 저장강박 성향 | DHQ 10문항 (축적, 삭제 어려움) | Neave 외(2019) |
| 조작 점검 | 넛지를 제대로 인식했는가 | "화면에서 어떤 안내를 받았나요?" | — |
| 통제변수 | 스토리지 이용 현황, 유료 이용 여부, 나이, 성별 | 설문 | — |

해외 척도는 **번역-역번역**으로 한국어판을 만들어야 함 (척도 번역 절차를 논문에 기술).

## 4. 참가자

- **대상:** 클라우드 스토리지(Google Drive, iCloud, 네이버 MYBOX 등)를 쓰고 있는 성인
- **모집:** 온라인 패널(엠브레인, 오픈서베이 등) 또는 학교 커뮤니티·SNS
- **표본 크기:** 중간 효과 크기(f = 0.25), 유의수준 .05, 검정력 .80 기준 (최종 확정 시 G*Power로 다시 계산)
  - 조건 5개: 약 **200명** (조건당 40명)
  - 조건 4개: 약 180명 (조건당 45명)
  - 2×2 설계: 약 128명 (조건당 32명)
  - 불성실 응답 제외를 고려해 10~20% 더 모집

## 5. 절차

1. 동의서 → 스토리지 이용 현황 설문
2. DHQ (실험 전에 측정해야 넛지의 영향을 받지 않음)
3. 무작위 조건 배정 → 용량 부족 상황 + 넛지 화면 제시
4. 선택 (정리 / 결제 / 무시)
5. 지각된 위협·정리 효능감(·반응 비용), 반발, 침해감, 정리·결제 의향, 서비스 태도 설문
6. 조작 점검, 인구통계
7. 실험 목적 안내(디브리핑)

예상 소요 시간: 10~15분

## 6. 분석 계획

- 조건별 선택 비율 비교 → 카이제곱 검정 또는 다항 로지스틱 회귀
- 조건별 반발·의향 비교 → 일원분산분석(ANOVA) + 사후 검정
- H2-1·H2-2 (방향 가설) → 계획된 대비: 손실 강조 vs 통제(지각된 위협), 추천·기본값 vs 통제(정리 효능감)
- 저장강박 성향의 조절 효과 → 조절 회귀분석 (PROCESS macro Model 1)
- 반발이 넛지와 행동 사이를 매개하는지 (탐색) → 매개 분석 (PROCESS Model 4)
- 지각된 위협·정리 효능감이 넛지와 정리 행동/의향 사이를 매개하는지 (H2-3) → 병렬 매개 분석 (PROCESS Model 4, 다범주 독립변수는 통제 조건 기준 더미 코딩)
